# 卡片库、二次整理与论文提纲优化报告

日期：2026-08-31  
优化前基线：`8d54eb8 feat: add database backup and recovery`

## 优化边界

本轮只改善三个既有工作区的浏览效率、信息查找和大量数据下的响应速度，不改变数据语义：

- 卡片库仍是当前项目全部卡片的永久总库。
- 从二次整理剔除仍然不是删除，卡片继续保留在卡片库与来源文献下。
- 卡片进入论文提纲仍只建立关联；从章节移除只解除该关联。
- 不新增自动写作、自动观点、自由画布或其他无关功能。

## 优化前发现的问题与准备改动

### 1. 卡片库

发现的问题：

- 文献分组通过“每篇文献重新筛一遍全部卡片”计算，文献和卡片同时增多时会产生不必要的重复遍历。
- 文献虽然可以整体收起，但单篇文献拥有大量卡片时，展开后仍会形成很长的页面。
- 缺少按“整理中 / 已剔除”快速缩小范围的入口；研究者只能依赖文字搜索逐张辨认。

准备改动：

- 一次性建立“文献—卡片”索引，避免重复筛选。
- 单篇文献默认分段显示卡片，并提供明确的“展开其余 / 收起”操作；搜索时始终显示全部匹配项。
- 增加不改变数据的整理状态筛选，并同时显示筛选后的卡片数量。

### 2. 二次整理

发现的问题：

- 每个分类都会重新遍历全部整理中卡片，分类和卡片增多后重复计算明显。
- 整理板没有跨分类搜索；寻找某条卡片时需要横向逐列浏览。
- “已剔除”列表也没有搜索，积累较多后恢复目标卡片较慢。

准备改动：

- 一次性建立“分类—卡片”索引。
- 在整理中与已剔除两个视图共用延迟搜索，覆盖摘录、评论、文献、作者和标签。
- 搜索时只改变可见结果，不改变分类、剔除状态或拖拽语义；显示匹配数量和空结果提示。

### 3. 论文提纲

发现的问题：

- 渲染每个章节时会反复扫描章节关联和全部卡片；卡片池又会为每张卡片重复扫描使用位置。
- 多级提纲总是完整展开，章节、子章节和证据卡片较多时结构难以快速浏览。
- 卡片池可以搜索，但不能快速隐藏已经关联到当前章节的卡片。

准备改动：

- 预先建立“章节—关联”“卡片—章节”“卡片 ID—卡片”“章节 ID—章节”索引。
- 为含子章节或证据的章节增加收起 / 展开，收起只影响显示，不修改章节或关联。
- 卡片池增加“隐藏本章已关联”筛选，并保留“还被哪些章节使用”的提示。

## 验收标准

- 搜索、筛选、分段显示和章节收起均不写入或复制业务数据。
- 卡片库筛选后仍可查看原文、编辑、定位二次整理和执行原有永久删除确认。
- 二次整理搜索后仍可拖拽、下拉移动、编辑和剔除；清空搜索后位置保持不变。
- 提纲收起后可重新展开，章节层级、章节内卡片顺序和多章节关联保持不变。
- 前端测试、Rust 测试、TypeScript、Clippy、Web 构建和 Tauri release 构建全部通过。

## 完成后的实际结果

### 卡片库

- 新增“全部 / 整理中 / 已剔除”状态筛选；筛选和搜索只改变当前可见范围，不改变卡片状态。
- 搜索继续覆盖摘录、评论、文献、作者和标签，并显示当前结果数量。
- 一次建立“文献—卡片”和“分类 ID—分类”索引，替代渲染期间按文献、按卡片反复扫描。
- 单篇文献默认显示前 10 张卡片，可按文献展开其余卡片；搜索时自动显示全部匹配结果。

### 二次整理

- 整理中与已剔除视图共用跨分类搜索，显示当前视图的匹配数量和明确的空结果提示。
- 一次建立“分类—卡片”和“分类 ID—分类”索引，分类增多时不再为每列重新扫描全部卡片。
- 搜索时自动展开匹配结果，并暂时停用无可见效果的收起操作；从卡片库定位卡片时会清空旧搜索条件，确保目标可以被找到。
- 原有拖拽、下拉移动、分类编辑、剔除与恢复路径保持不变。

### 论文提纲

- 一次建立卡片、章节、章节关联和卡片使用位置的双向索引，替代逐章节、逐卡片的重复查找。
- 含子章节或证据卡片的章节可收起；收起会隐藏全部后代和本章证据，但不修改数据库中的层级、顺序或关联。
- 卡片池可隐藏已关联到当前章节的卡片，并继续提示每张卡片还在哪些章节使用。
- 当前选择若因层级变化而被隐藏，会自动回到仍可见的章节，避免继续向不可见章节添加卡片。

### 验证结果

- TypeScript 类型检查通过。
- Vitest：8 个测试文件、27 项测试全部通过；新增卡片筛选、分组、提纲索引和章节收起测试。
- Rust：17 项 SQLite、备份恢复、重新链接和业务不变量测试全部通过。
- Clippy（警告视为错误）通过。
- Vite production 构建通过。
- Windows Tauri release 构建通过，产物为 `src-tauri/target/release/inkstone-research.exe`。

### 本轮未纳入

- 搜索词、文献分段展开状态和章节收起状态属于临时界面状态，应用重启后会恢复默认显示；业务数据不受影响。
- 本轮未增加虚拟滚动、SQLite 全文索引或分页读取。现阶段先通过一次性索引、延迟搜索和分段显示减少重复计算；当真实资料量达到需要数据库分页的规模后再单独评估。
- 未加入 WPS 剪贴板、自由画布、NoteExpress 导入或生成式 AI 功能。
