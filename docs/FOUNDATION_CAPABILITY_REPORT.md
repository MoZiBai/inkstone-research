# 砚台基础能力补全报告

日期：2026-08-31  
开发基线：`980e43b fix: merge database imports without replacing projects`

## 目标边界

本轮在现有本地应用中完善卡片记录、研究作用、内容编辑、备份安全和大量资料下的基础效率。继续遵守以下不变量：

- 卡片库是当前项目全部卡片的永久总库。
- 从二次整理剔除不是删除。
- 卡片进入提纲只建立关联，从章节移除只解除关联。
- 原始 PDF、不可变选区文字和定位信息不会因修改卡片显示文字而改变。
- 数据库导入采用非破坏性合并，不替换现有项目。
- 本轮不加入生成式 AI、自动写作、云同步、自由画布、NoteExpress 或 WPS 剪贴板功能。

## 阶段一：轻量卡片记录与多研究作用

状态：已实现，提交 `c1b23a4 feat: make card research roles flexible`。

### 数据模型

- 数据库版本由 6 升级到 7。
- 新增 `research_roles`，研究作用归属于项目，保存名称、颜色、顺序、默认项和归档状态。
- 新增 `project_card_roles`，通过关联表支持一张卡片拥有多个研究作用。
- `project_cards` 新增 `origin_kind`，区分普通摘录、由灵感转换和由质疑转换。

### 用户流程变化

- 创建卡片时不再要求立即选择“支持、反对、限定、背景”。

- 二次整理新增研究作用管理，可创建、重命名、改色、排序、归档和重新启用。
- 归档研究作用不会移除已有卡片关联；已选中的归档作用仍会在卡片详情中显示。

### 转换与数据安全

- 灵感或质疑转为卡片时，来源类型在删除阅读笔记前写入卡片。
- 创建卡片、自动高亮和删除原阅读笔记仍处于同一数据库事务。
- 如果相同原文已经存在项目卡片，转换不会删除原阅读笔记。
- 整体数据库和单项目合并导入同步复制研究作用及其卡片关联，并继续使用 ID 与业务唯一键解析重复对象。

## 阶段三：备份管理与数据库导入预览

状态：已实现，提交 `97d7de3 feat: add managed backups and import previews`。

### 数据模型与迁移

- 数据库版本由 7 升级到 8，新增 `backup_records`，登记自动安全备份、完整数据库导出和单项目数据库导出的路径、类型、项目、大小、受管理目录及创建时间。
- 自动备份目录、保留天数及最近清理结果保存在 `app_metadata`，应用重启后继续生效。
- 单项目导出会移除本机备份记录和备份目录设置，避免把与项目无关的本机路径带入项目文件。
- 数据库合并不导入另一台设备的备份目录与清理设置；备份管理设置始终属于当前应用安装环境。

### 备份管理

- “备份与恢复”中可以查看应用登记的备份时间、类型、大小、文件路径、文件可用性和当前总占用空间。
- 可以打开当前自动备份目录、选择并验证自定义目录、恢复默认目录，以及定位单个仍存在的备份文件。
- 更换目录不会移动或删除旧目录中的备份；自定义目录失效时会明确提示并回退默认目录。
- 默认从不自动清理；可选择 7、30、90、180 天或 1–3650 天的自定义保留期。
- 自动清理只逐个处理砚台登记、命名合法且位于当前受管理目录中的自动安全备份；始终保留最近 3 份有效自动备份。
- 手动导出的完整数据库和单项目数据库不参与自动清理。手动删除也只对自动安全备份开放，并显示文件名、时间和大小后二次确认。
- 清理结果记录删除数量、释放空间、失败数量和最近执行时间；单个文件失败不会中止其他文件的处理。
- 界面明确说明数据库备份不复制 PDF 原件，只保存研究数据、文献元数据和 PDF 路径。

### 非破坏性导入预览

- 选择完整数据库或单项目数据库后，先在只读预览流程中验证完整性、迁移临时副本并统计内容，不会立刻修改当前资料库。
- 预览显示项目、文献、卡片、PDF 批注和提纲节点数量，以及预计新增记录、合并已有项目、跳过相同记录、内容冲突和缺失 PDF 数量。
- “冲突”表示稳定标识相同但内容不同；当前资料库版本会被保留，不会被来源文件静默覆盖。
- 确认导入后必须先成功创建自动安全备份，再执行合并；随后显示与预览相同口径的详细结果、备份路径、目录回退警告及自动清理结果。
- 重复导入继续保持幂等；项目、文献、卡片、批注、分类、研究作用和提纲关联不会因重复导入膨胀。

## 阶段五：大量资料下的基础效率

状态：已实现，提交 `50a9dae feat: add large-library efficiency tools`。

### 项目、文献与统一搜索

- 项目侧栏支持按名称和说明搜索，并可筛选有文献、有卡片或空项目；排序支持最近更新、名称、文献数和卡片数。
- 阅读台文献栏支持搜索标题、作者、期刊、出版社、DOI 和年份；可按 PDF 可用、尚未连接和 PDF 缺失筛选，并按最近更新、标题、作者、年份或卡片数排序。
- 顶部新增当前项目统一搜索，结果按文献和卡片分组。文献覆盖标题、作者、期刊、出版社与 DOI；卡片覆盖显示摘录、即时笔记、来源标题、作者和标签。
- 点击统一搜索结果会进入阅读台并打开相应文献；卡片结果会继续跳转到其 PDF 页码和原文定位。

### 批量 PDF 导入

- 正常导入入口允许一次选择多个 PDF；重新链接已有文献时仍只允许选择一个文件，避免把多个文件误连到同一文献。
- 批量导入逐份执行并逐项显示文件、标题、成功或失败状态及具体错误；某一文件失败不会中止其余文件。
- 批量导入先以 PDF 文件名建立可编辑标题，导入后可继续使用现有书目信息编辑和引用格式识别补充作者、年份、期刊与 DOI。
- 单文件导入继续保留原有完整书目编辑流程，不因批量能力而降级。

### 卡片批量操作

- 卡片库和二次整理均支持多选、选择当前搜索结果和清除选择。
- 批量工具栏始终显示影响卡片数量，可批量添加标签、移除标签、移动整理分类、从二次整理剔除和恢复。
- 新增后端 `batch_update_cards`，全部变更在单个 SQLite 事务内完成；先验证卡片均属于当前项目、分类有效且标签数量合法，再统一提交。
- 跨项目或无效卡片会让整个事务失败，不会出现只修改一部分卡片的状态；剔除仍只改变整理状态，不删除卡片、原文或提纲关联。

### PDF 文内搜索

- 阅读器支持 `Ctrl+F` 打开当前 PDF 搜索，也可使用工具栏“查找”按钮。
- 搜索通过 PDF.js 逐页提取文字内容并缓存，显示当前序号和总匹配数量；Enter / Shift+Enter 或按钮可前后循环跳转。
- 跳转会加载相应懒渲染页面，并在文字层突出全部命中和当前命中。
- 搜索标记只存在于 PDF.js 文字层，关闭搜索会清除搜索状态，不会创建、修改或删除研究卡片高亮、PDF 高亮和下划线批注。
- 对超长 PDF 的索引会分批让出主线程；无文字层的扫描 PDF 仍需后续 OCR 才能搜索。

- 点击 PDF 原文上的高亮或下划线即可在紧凑菜单中直接选择颜色、编辑评论或删除，不再要求先到右侧栏打开大颜色弹窗。

### 分级文献分类与数据安全

- 数据库版本由 8 升级到 9，新增 `document_groups`；分类属于项目，使用 `parent_id` 支持任意层级，并保存稳定 ID、顺序和时间。
- `project_documents.group_id` 只保存项目中文献与分类的关联。同一 PDF 仍可被多个项目独立分类，不复制文献文件，也不改变共享来源摘录。
- 阅读台可创建一级分类、从分类右键创建下级分类、重命名或调整上级；非法跨项目父级、自身父级和移入自身后代会由后端拒绝。
- 文献可通过文献右键菜单或右侧“当前文献”区调整分类；分类树可逐级展开和收起，搜索或筛选时自动保留匹配文献及其祖先路径。
- 移除分类会同时移除其下级分类，但所有文献安全回到“未分类”；PDF、卡片、批注、阅读笔记、二次整理状态和论文提纲均不删除。
- 完整数据库合并、单项目导出 / 导入、导入预览和重复导入表清单均包含文献分类及 `group_id`；旧 v8 数据库迁移后所有文献默认保持“未分类”。

## 已知限制与后续能力

- 扫描 PDF 没有可用文字层时，文内搜索和文字选择仍依赖后续 OCR 引擎接入。
- 批量 PDF 导入不会把一个引用格式同时套到多篇文献；当前先以文件名建题名，书目信息需逐篇补充或编辑。
- PDF 全文搜索当前执行文字型 PDF 的确定性字符串匹配，不提供模糊匹配、词形还原或跨文献全文索引。
- PDF.js worker 与阅读器仍形成较大的前端 chunk；当前不会影响离线运行，但后续可通过按需加载进一步缩短首次启动资源解析时间。
- 文献分类当前按创建顺序稳定排列，支持调整父级但尚未提供同级拖拽排序；文献移动使用明确的分类选择器，尚未在树中实现拖拽。
