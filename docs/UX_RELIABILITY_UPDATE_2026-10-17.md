# 界面、连续性与可靠性改动记录

日期：2026-10-17

实施前代码基线：`8b066a2`

本文是本轮开发和验证记录，不是新增产品需求。范围对应已选定的五组审查事项；独立想法卡片仍待单独确认。

## 本轮已实施

### 安全与正确性

- 数据库迁移整体放入事务：升级失败时，表结构和版本标记一起回滚，可以修正问题后重试。遇到高于当前支持版本的资料库，明确拒绝打开，而不是继续写入。
- 数据库版本仍为 12，没有为界面调整增加业务表或改变摘录、分类、提纲的存储语义。
- 窗口关闭和托盘退出统一进入退出检查；有未保存编辑时需要再次确认，正在写入、导入或备份时阻止直接退出。隐藏到后台不会放弃编辑。
- 后端退出会等待数据库锁释放；自动备份在退出信号后不再启动新的任务。
- 自动备份报告运行中、下次计划时间和失败原因。失败后安排一分钟重试，数据库繁忙时不抢占正在进行的写入。调度检查间隔为 10 秒，不承诺严格实时触发。
- 保留既定规则：每次启动重新计时，隐藏到托盘继续计时，完全退出停止，不在再次启动时补做离线期间的备份。
- 批量选择限制在当前筛选结果内，切换筛选或剔除视图后移除范围外的选择；按钮明确说明是选择全部筛选结果，包含尚未分段显示的结果。
- 同步阻止重复提交；保存成功但刷新失败时明确提示“已保存”，保留旧快照和重试入口，避免用户重复保存。
- PDF 查找快捷键只在阅读台启用；对话框和其他输入框不会被阅读器的 Ctrl+F 抢占。右键文字命令失败时提示使用相应快捷键，不再静默无响应。

### 操作连续性

- 记忆上次项目、工作区、各项目正在阅读的文献、PDF 页码、页内相对位置、横向位置和缩放方式。
- 隐藏阅读台时不再用零尺寸页面覆盖已记忆的阅读位置。
- 项目列表与文献列表的搜索、筛选、排序，以及卡片库、整理板、提纲的搜索和主要展开状态在本机记忆；无效的文献或分类筛选会在对应对象删除后复位。
- 顶部项目搜索离开焦点后收起结果但保留输入；显示完整匹配数量，可以逐步加载更多结果。文献结果恢复阅读位置，卡片结果先打开详情，也可继续查看原文。
- 原文定位在阅读器准备好后完成并消费请求，避免固定延时过早失效，或者重新打开文献时重放旧的定位请求。
- 从卡片详情查看原文时关闭已无修改的详情窗，避免隐藏的对话框继续拦截阅读快捷键；有未保存修改时仍要求先处理修改。

### 界面一致性

- 卡片库、整理板、提纲卡片池和阅读侧栏复用卡片正文展示：个人笔记在前，原文摘录单独分隔，页码信息降低视觉权重。
- 标签输入、建议和移除统一，支持中文顿号、逗号、英文逗号、分号和换行分隔；批量标签面板可取消、点外部或按 Esc 收起，取消不保留草稿。
- 右键菜单按实际尺寸避让窗口边缘，支持方向键、Home、End 和 Esc；空白区域不再出现无关的工作区切换菜单。
- 阅读右栏可整体收起，内部区块独立展开；提供“当前页 / 整篇文献”范围，卡片和批注优先显示当前页，列表分段加载。
- 提纲卡片池可调整宽度，按文献或整理分类筛选；使用位置提示包含完整章节路径，减少同名小节混淆。
- 整理卡片和提纲节点使用明确拖动把手，避免选择文字、操作按钮时误拖；保留原来的下拉移动方式。
- 备份列表明确区分文件存在和文件缺失，可以直接选择一份备份进入原有安全合并预览，不改变非破坏性合并规则。
- 用户界面和使用指南统一采用“写作提纲”“卡片用途”“阅读项目”等名称，窗口标题改为“砚台 · 阅读与思考”。内部包名、数据库标识和既有数据目录不改名，避免丢失现有资料入口。

### 结构与性能

- 拆出备份窗口、退出窗口、卡片正文、标签编辑、格式化、界面偏好、阅读位置和局部刷新模块。
- 普通修改只重新查询受影响的工作区数据。文献移除、项目变化、资料库合并等结构变化仍完整刷新；请求项目不存在时也完整加载回退项目。
- 前端合并局部快照时保留无变化数组的引用，避免每次批注都重建卡片和文献数据；旧的异步刷新结果不会覆盖较新的结果。
- 常用数据库操作和备份管理查询转入后台任务，避免在原生窗口线程等待数据库锁。
- 卡片库默认每篇预览 10 张，展开或搜索后按 50 张加载；整理板展开列表和提纲卡片池按 50 张加载；阅读侧栏与备份列表按 30 条加载。所有记录仍保留，可继续显示。
- PDF 阅读器按需加载；保留可见页渲染，限制单页渲染画布的像素预算，避免高倍缩放时无节制增加内存。CSS 阅读缩放和文字定位坐标不因此降低。

## 明确保留的产品规则

- 卡片库仍是全部卡片的永久总库，筛选和分段显示都不是删除。
- 整理剔除可恢复，不影响提纲关联。
- 提纲使用卡片仍只建立关联，多章节引用不复制原始摘录；移除关联不删除卡片。
- 原始摘录和个人编辑内容分开，PDF 原件不修改。
- 完整备份和项目导入仍采用已有的安全合并与导入前备份流程。
- 没有增加独立想法卡片、AI 自动观点、自动写作、自由画布或外部文献管理器导入。

## 验证结果

- TypeScript 类型检查通过。
- 前端测试 57 项通过，覆盖标签规则、阅读偏好恢复、画布预算、局部刷新依赖、完整搜索计数、章节路径、长列表渲染边界等。
- Rust / SQLite 测试 47 项通过，新增覆盖升级失败回滚、拒绝未来版本、局部查询与项目回退、失败备份重试。原有卡片状态、提纲关联、文件重连和安全合并回归测试继续通过。
- Rust 格式化及 Clippy 严格检查通过。
- 1000 张卡片的服务端渲染检查确认：卡片库默认只渲染 10 张，展开整理分类和提纲卡片池各只渲染首批 50 张。
- 合成 10000 张卡片的筛选、分组、索引组合测试约 6～10 毫秒；这只是纯数据处理测试，不代表实际 PDF 阅读帧率或整应用性能。
- Windows release 构建通过，产物为 `src-tauri/target/release/inkstone-research.exe`。
- 前端主入口约 400.5 KB，PDF 阅读模块约 635.2 KB，分离为按需加载。构建仍提示 PDF 模块超过 500 KB；未通过调高阈值隐藏该提示，它不是构建失败。

测试使用项目内临时资料或内存数据库；没有打开、扫描或修改用户正在使用的实际资料库和 PDF 集合。

## 仍需区分的能力边界

1. 本轮没有进行 Windows 窗口的实际点击、托盘操作或真实 PDF 的视觉验收。不同 DPI、页尺寸混杂的大 PDF、实际文字选区与批注定位仍需实机检查；不能把类型检查和渲染测试当成这些交互已经验收。
2. 长列表采用分段显示，不是完整虚拟滚动；项目首次载入仍读取该项目业务数据，不是数据库分页。超大资料库与大量 PDF 的端到端性能尚未测量。
3. 拆分是渐进的，阅读台和数据仓库仍较大，没有在同一轮进行高风险的全面重写。
4. 阅读位置和界面偏好保存在本机界面存储，不随数据库备份迁移。数据库中的卡片、批注、分类、提纲和文献关系仍按原规则备份。
5. 没有新增 OCR、跨页摘录、全文索引或 Word/Markdown 导出。文献级灵感、质疑如何成为独立卡片，仍等待产品确认。
6. Git 检查点只保存代码和文档，不替代资料库备份；构建产物、临时数据库、PDF 和私人配置不纳入提交。本轮不向 GitHub 推送。
